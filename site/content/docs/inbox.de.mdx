Die Inbox ist eine Liste aller offenen Pull Requests aus all deinen Repositories. Shepherd füllt sie alle paar Minuten mit ein paar GitHub-Suchen und speichert das Ergebnis in einer lokalen Datenbank. Mit `⌘R` synchronisierst du sofort.

![Die Shepherd-Inbox](/inbox.png)

## Was angezeigt wird

Die linke Seitenleiste hat diese Ansichten:

| Ansicht | Was drin ist |
| --- | --- |
| **Braucht mein Review** | Pull Requests, bei denen ausdrücklich dein Review angefragt wurde und die noch kein Approval haben. |
| **Meine Pull Requests** | Pull Requests, die du geöffnet hast. |
| **Beteiligt** | Alles, was Shepherd für dich synchronisiert: Review angefragt, dir zugewiesen, von dir geöffnet, du wurdest erwähnt, oder alles andere, was GitHub als Beteiligung zählt. |
| **Beobachtet** | Offene Pull Requests in [beobachteten Repositories](#beobachtete-repositories), an denen dich niemand beteiligt hat. |
| **Von mir approved** | Eine Annäherung. GitHub kann nicht nach "das habe ich approved" suchen. Hier siehst du deshalb Pull Requests, bei denen dein Review angefragt war und die jetzt ein Approval haben. |

Ein Pull Request, an dem du auch beteiligt bist, bleibt unter **Beteiligt**, selbst in einem beobachteten Repository. Nur Zeilen ohne andere Verbindung zu dir landen unter **Beobachtet**.

Geschlossene und gemergte Pull Requests verschwinden aus der Inbox. Draft-Pull-Requests bleiben drin und tragen einen **Draft**-Chip.

Neben den Pull Requests gibt es einen zweiten Bereich für Issues. Mit der Auswahl oben in der Seitenleiste wechselst du zwischen **Pull Requests** und **Issues**.

### Einen Pull Request ausblenden

Klicke eine Zeile mit der rechten Maustaste an und wähle **Diesen Pull Request ausblenden**. Ein Hinweis bietet **Rückgängig** an. Eine neue Review-Anfrage holt einen ausgeblendeten Pull Request zurück. Die vollständige Liste findest du unter Einstellungen → Sync bei **Ausgeblendete Pull Requests**.

## Beobachtete Repositories

Wenn du ein Repository beobachtest, kommt jeder offene Pull Request darin in die Inbox, auch die, bei denen dich niemand gefragt hat. Du kannst bis zu 10 Repositories beobachten. Jedes ist eine weitere Suche bei jedem Durchlauf.

So fügst du eines hinzu:

1. Klicke in der Seitenleiste auf das `+` neben **REPOSITORYS** oder drücke `⇧⌘A`.
2. Wähle **Repository beobachten…**.
3. Tippe `owner/repository` oder füge eine GitHub-URL ein und klicke auf **Beobachten**.

Die Liste kannst du auch unter Einstellungen → Sync bei **Beobachtete Repositories** verwalten. Beobachtete Repositories stehen ganz oben im Bereich **REPOSITORYS**, mit einem Fernglas-Symbol, auch wenn die aktuelle Ansicht nichts von ihnen enthält.

![Beobachtete Repositories in der Seitenleiste](/watched-repositories.png)

### Einen lokalen Clone hinzufügen

Wähle **Lokales Repository hinzufügen…** im selben `+`-Menü oder über `⌘K`. Wähle den Ordner eines Clones. Shepherd liest `owner/repo` aus dem `origin`-Remote und zeigt eine Bestätigung mit zwei Kästchen:

- **Diesen Ordner als lokalen Checkout verknüpfen**
- **Das Repository beobachten**

Beide sind standardmäßig angehakt. Du kannst jedes abwählen.

Ein beobachtetes Repository mit verknüpftem Clone zeigt ein kleines Laptop-Symbol. Mit Rechtsklick siehst du **Agent starten…**. Ohne Clone bietet das Menü stattdessen **Lokalen Checkout verknüpfen…** an.

<Callout type="info">
Nur github.com wird unterstützt. Ein Clone, dessen `origin` auf GitHub Enterprise zeigt, wird abgelehnt.
</Callout>

## Gruppieren, sortieren und filtern

### Gruppieren

Das Menü **Gruppieren** über der Liste hat drei Optionen:

| Option | Kürzel | Abschnitte |
| --- | --- | --- |
| **Agent** | `g a` | Einer pro erkanntem Coding-Agent, dann Bots, dann Menschen. |
| **Repository** | `g r` | Einer pro Repository, nach Name. |
| **Review-Status** | `g s` | Review erforderlich, Changes requested, Approved, Keine Review-Entscheidung. |

Shepherd erkennt Agents wie Claude Code, GitHub Copilot, OpenAI Codex, Devin und Cursor am Login des Autors, am Branch-Präfix oder an Commit-Trailern. Die Liste kannst du unter Einstellungen → Agenten anpassen.

### Sortieren

Das Menü **Sortieren** bietet **Priorität**, **Kürzlich aktualisiert** und **Älteste zuerst**. Die Reihenfolge bleibt stabil, solange Syncs dieselben Daten liefern. Die ausgewählte Zeile bleibt an ihrem Platz, bis du weitergehst.

### Mit der Seitenleiste filtern

Unter den Smart-Ansichten hat die Seitenleiste Facetten. Klicke eine an, um die Liste zu filtern. Klicke sie noch einmal an, um den Filter zu löschen, oder nutze das x neben dem Filter-Chip im Listenkopf.

- **SPUREN** mit **Kurzer Blick** und **Vollständiges Review**.
- **RISIKO** mit **Niedriges Risiko**, **Mittleres Risiko** und **Hohes Risiko**.
- **AGENTEN**, eine Zeile pro Agent, dazu **Bots** und **Menschen**.
- **REPOSITORYS**.

Eine Facette, die zu einer leeren Liste führen würde, wird nicht angezeigt.

### Mit ⌘K suchen

`⌘K` öffnet die Befehlspalette und durchsucht auch deine Pull Requests und Issues nach Bedeutung. Tippe zwei, drei Wörter oder eine Referenz wie `owner/repo#128` oder `#128`. Jedes Ergebnis sagt, warum es passt.

Du kannst Filter ergänzen: `risk:high` und `kind:dependency`. Mit `⏎` öffnest du ein Ergebnis.

Die Suche läuft nur auf deinem Mac. Sie nutzt nie einen KI-Endpunkt, auch wenn du einen eingerichtet hast. Unter Einstellungen → Intelligenz siehst du den Index, dazu gibt es den Button **Index neu aufbauen** und einen Schalter.

## Triage-Tags

Jede Zeile kann einen kleinen Tag tragen, zum Beispiel `fix · Risiko hoch`. Klicke ihn an, um den Grund dahinter in einem Satz zu sehen.

- Die Art ist eine von **feature**, **fix**, **chore**, **dependency**, **docs** oder **refactor**.
- Das Risiko ist **Risiko niedrig**, **Risiko mittel** oder **Risiko hoch**.
- Das Urteil schreibt Apples On-Device-Modell auf deinem Mac. Nichts wird irgendwohin gesendet.
- Ohne Apple Intelligence greift der Tag auf Risiko-Hinweise zurück, die aus den geänderten Dateien berechnet werden, zum Beispiel nur `Risiko hoch`.

Der Tag ist ein Label und ein Filter. Er ändert die Reihenfolge der Liste nicht, und keine Regel, keine Sammelaktion und keine Automatisierung liest ihn.

Schalte ihn unter Einstellungen → Intelligenz mit **Pull Requests einordnen** aus. Damit werden die gespeicherten Urteile gelöscht.

## Zwei Spuren

Ein Pull Request ist nur dann ein **Kurzer Blick**, wenn alles davon zutrifft:

- Die CI ist grün.
- Der Diff ist klein. Standard sind 5 Dateien und 120 geänderte Zeilen.
- Nichts Heikles ist enthalten: kein CI-Workflow, kein Auth- oder Secret-Pfad, keine Schema-Migration und kein gelöschter Test.

Alles andere ist ein **Vollständiges Review**. Ein Pull Request, dessen Diff Shepherd noch nicht geladen hat, ist ein vollständiges Review. Die beiden Grenzen änderst du unter Einstellungen → Automatisierung.

### Erfolgsbilanz der Agents

Shepherd kann zeigen, wie die Pull Requests jedes Agents in einem Repository abgeschnitten haben: Merges, Reverts und wie oft die CI beim ersten Push grün war. Das färbt nur den Agent-Chip ein und entscheidet bei Gleichstand die Sortierung. Ein Pull Request wechselt dadurch nie die Spur.

Die Zahlen stammen aus den geschlossenen Pull Requests der letzten 90 Tage, höchstens 500 pro Repository. Lade sie einmal mit **Erfolgsbilanz laden** unter Einstellungen → Automatisierung. Die Inbox bietet es außerdem einmal in einem Hinweis über der Liste an. **Historie löschen** leert sie. Die Historie bleibt auf diesem Mac.

## Die Flotte

Die Zeile **Flotte** unten in der Seitenleiste listet jeden Agent, den Shepherd gesehen hat. Für jeden siehst du, wie viele seiner Pull Requests offen sind, wie viele auf dich warten und was mit denen passiert ist, die er in den letzten 90 Tagen geschlossen hat. Klicke einen Agent an für eine Seite mit denselben Zahlen pro Repository.

Die Flotte hat keine Bewertung und kein Ranking. Für die Zahlen zu geschlossenen Pull Requests braucht sie die Erfolgsbilanz von oben. Bis du sie lädst, steht dort ein Strich.

## Mehrere Pull Requests auswählen

Jede Zeile hat ganz links ein Kästchen. Es ist blass, bis du auf die Zeile zeigst oder etwas angehakt hast.

- Klicke das Kästchen an, um eine Zeile anzuhaken.
- Drücke `x`, um die Zeile unter dem Cursor anzuhaken.
- `⌘`-Klick auf eine Zeile hakt sie an.
- `⇧`-Klick auf eine Zeile hakt den Bereich vom Cursor bis zu dieser Zeile an.
- Mit `esc` oder einem Klick auf das x neben dem Chip hebst du die Auswahl auf.

Solange etwas angehakt ist, zeigt der Kopf einen Akzent-Chip mit der Anzahl, zum Beispiel **3 ausgewählt**.

Wähle **Alle grünen Agent-Pull-Requests auswählen** im Checklisten-Menü der Symbolleiste, im Rechtsklick-Menü oder über `⌘K`. Das hakt jeden von einem Agent geschriebenen Pull Request in der aktuellen Ansicht an, der kein Draft ist, grüne CI hat, mergebar ist und keine Änderungsanforderung hat. Pull Requests von Menschen werden nie mit erfasst.

### Sammelaktionen

Das Checklisten-Menü in der Symbolleiste heißt **Sammel-Triage** und wird zu **Triage: n ausgewählt**, sobald Zeilen angehakt sind. Es bietet:

- **Auswahl approven…**
- **Auswahl approven & mergen…**
- **Auswahl mergen…**
- **Nacheinander mergen…**, für eine Serie in einem Repository. Siehe [Mergen](/de/docs/merging).

Dieselben Aktionen findest du in `⌘K` und im Rechtsklick-Menü einer angehakten Zeile. Jeder Bestätigungsdialog listet auf, was eingereiht und was übersprungen wird, mit Grund, zum Beispiel rote CI, Konflikte, Drafts, angeforderte Änderungen oder dein eigener Pull Request. Jeder Pull Request wird einzeln eingereiht, mit derselben Offline- und Retry-Behandlung wie ein einzelnes Review. Siehe [Reviewen](/de/docs/review#sammel-triage) und [Mergen](/de/docs/merging).

## Schnelle Inbox in der Menüleiste

Das Menüleisten-Symbol zeigt, wie viele Pull Requests auf dein Review warten. Klicke darauf für eine kurze Liste mit bis zu acht, die dringendsten zuerst. Jede Zeile zeigt Repository und Nummer, den Titel, den Autor und den CI-Status. Ein Klick auf eine Zeile öffnet das Review im Hauptfenster. Unten findest du **Jetzt synchronisieren** und **Shepherd öffnen**.

Sie liest dieselben lokalen Daten wie die Inbox. Schalte sie unter Einstellungen → Darstellung mit **In der Menüleiste zeigen** aus.

## Morgen-Digest

Standardmäßig aus. Schalte ihn unter Einstellungen → Sync mit **Morgen-Digest senden** ein. Die Uhrzeit stellst du unter **Um** ein, und mit **Nur an Wochentagen** kannst du ihn auf Werktage beschränken. Standardzeit ist 9:00.

Einmal am Tag bekommst du eine Mitteilung, die die Inbox öffnet, und dazu eine wegklickbare Karte über der Liste. Sie berichtet, was seit dem letzten Digest passiert ist:

- neue Review-Anfragen
- dir zugewiesene Issues
- grüne Agent-Pull-Requests, die nur noch ein Approval oder einen Merge brauchen
- Issues, die ein Agent-Pull-Request geschlossen hat
- deine eigenen Pull Requests mit roter CI oder einer Änderungsanforderung
- eingereihte Reviews, die nicht gesendet wurden, und Schreibvorgänge, die Shepherd aufgegeben hat

Jede Zeile hat einen **Zeigen**-Button, der dich hinbringt. Der Digest entsteht nur aus lokalen Daten. Wenn dein Mac zur eingestellten Zeit geschlafen hat, kommt er beim Aufwachen, sofern es noch derselbe Tag ist. Eine ruhige Nacht erzeugt nichts.

## Mitteilungen

Unter Einstellungen → Sync gibt es unter **Mitteilungen** drei Schalter:

- **Ein neues Review wird von mir angefordert**
- **Checks auf einem Pull Request von mir fehlschlagen**
- **Ein eingereihtes Review konnte nicht gesendet werden**

macOS fragt beim ersten Mal nach der Erlaubnis, wenn Shepherd eine Mitteilung sendet. Automatische Regeln und Webhooks haben eigene Mitteilungen. Siehe [Automatisierung](/de/docs/automation).
